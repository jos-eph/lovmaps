## 4. Decisions made on the user's behalf — flagged for review

### 4.1 Scope: this is a map-content change, which §7.3 reserves from agents

`AGENT_OPERATING_RULES.md` §7.3 says: *"Do not refactor map content / OMT normalisation logic
in `generate_tiles_pb.py`. Only its I/O surface."* Editing `ZOOM_FILTERS` is squarely map
content. I proceeded because `@jos-eph` gave explicit permission for C5/C6 in this session,
and because the human push gate (§7.2) means nothing reaches the repo without review.
**Flagged rather than assumed.** §7.3 may want a sentence describing when content changes are
in scope.

### 4.2 Rail/transit: implemented, then reverted on instruction

An earlier version of this commit also dropped `["all", [">=", "$zoom", 10], ["in", "class",
"rail", "transit"]]`, per the spec's C6, and inverted the test that pinned it. `@jos-eph`
asked for it back and that was the correct call. Three reasons, recorded so this is not
re-litigated:

* `test_rail_transit_still_admitted_at_zoom_10` existed **specifically** to hold that branch
  when the 08 spec gated the street classes — the word "still" marks a deliberate prior
  decision.
* This is a general-purpose tile source, not a BusNeighbor-private one. Rail is the most
  plausible thing another consumer wants. The spec's own risk R4 says so.
* The saving was ~0.33 MB at z13, **0.9%** of feature bytes, against `service`'s 8.61 MB and
  23.6%. Essentially the whole win is `service`.

The pinned test is restored byte-for-byte and now has a behavioral counterpart asserting
rail/transit survive at z10–13 and are correctly rejected at z9.

### 4.3 `place` state/county: declined, and filter-only would be actively worse

The spec described this as removing "25 features and ~0 bytes", for tidiness. That
understates what is there. `generate_tiles_pb.py` **synthesizes** those points deliberately:
`iter_state_labels` / `iter_county_labels`, a `STATE_LABEL_WHITELIST`, a junk filter that
removed 8 bad `class=county` entries, `minzoom: 6` tippecanoe directives on both, and a
build-failing label manifest. Removing only the `ZOOM_FILTERS` entries would leave all of
that running every build, producing features that tippecanoe then silently discards — dead
code that looks alive, for no measurable saving. Declined rather than half-done.

### 4.4 Branch naming

The BusNeighbor spec named the branch `perf/tile-diet_agent_permitted`. I used
`005/tile-diet_agent_permitted` to match this repo's existing convention
(`001/initial_setup`, `004/fix-boundary_agent_permitted`), keeping the required
`_agent_permitted` suffix. Say if the spec's name is preferred.

### 4.5 Base branch

Cut from `004/fix-boundary_agent_permitted`, **not** `main`. `main`'s `generate_tiles_pb.py`
is ~1,000 lines behind and its `ZOOM_FILTERS` has a different shape (`service` gated at z11,
no `$type` boundary guard). The spec's quoted filter matches 004, so 004 is the correct base.
**This means 005 carries all 30 unmerged commits of 004 and should land after it, or with it.**

### 4.6 Commit was amended

The rail/transit revert was folded into the original commit rather than added as a second
one, so the branch presents a single commit doing a single thing. Permitted: §7.2 forbids
amending a commit **that exists on origin**, and this one has never been pushed.
